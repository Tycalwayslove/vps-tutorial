# XHTTP 与传输选择

XHTTP 是 Xray 的一种传输方式。它与 VLESS 的关系，可以类比“请求格式”和“承载请求的方式”；不能把 XHTTP 当成所有代理协议都能点击使用的加速开关。先读 [[协议传输与安全层]]。

| 组合里的部分 | 你在决定什么 |
| --- | --- |
| VLESS 等代理协议 | 如何表达代理请求与使用身份 |
| RAW、WebSocket、XHTTP 等传输 | 数据用怎样的方式承载 |
| TLS、REALITY 等安全配置 | 怎样保护这段连接、验证对端 |

XHTTP 有不同工作模式及高级参数。要对照双方核心版本、模式、路径、安全层与中间代理能力配置；导入器能识别链接，不等于核心可以运行这一组合。[XHTTP 官方入口](https://xtls.github.io/config/transports/xhttp.html)

本次六条已验证的入口没有使用 XHTTP。已有 TCP/RAW 的 REALITY 入口不能仅把传输下拉框改为 XHTTP，就沿用所有字段并当作测试完成。尤其不要默认复制 Vision flow；应按当前组合的官方要求确认。

## 如果以后做对照实验

保留当前已验证入口，新建独立测试入口。记录服务端和客户端内核版本、传输模式、路径、安全层、端口及实际请求结果；确认可用后，再在同一目标和时段比较速度。这样才能分清是新传输有效，还是网络时段或其他配置变化造成差异。

当前主线继续用 [[VLESS-REALITY配置]]；历史兼容组合见 [[主流协议选择地图]]。本文不提供“最新一定最快”或“永不被识别”的结论。
