# 防火墙与监听地址

监听地址决定程序在哪个网络入口等待连接。`127.0.0.1` 是本机回环地址，像“只对本机开放的窗口”；`0.0.0.0` 常表示监听所有 IPv4 接口。

防火墙是按规则决定是否让数据通过的门禁。云服务商防火墙和 Linux 内部防火墙可能同时存在，需要逐层查看。

初始面板只监听 VPS 的 `127.0.0.1:46832`，通过 [[SSH隧道]] 访问。后来按用户要求，在面板中将监听 IP 改为 `0.0.0.0`，加载 TLS 证书并重启，现在可以公网 HTTPS 登录，详见 [[08-开放公网HTTPS面板]]。代理入站监听 tyccc 的公网 IPv4；公开订阅 2096 仍关闭。用 `ss` 核对监听，并从电脑直接验证公网连接。

“网页打不开”并不能直接推断为防火墙问题。依次确认地址正确、服务运行、程序监听、规则放行以及网络可达。

| 操作 | 能证明什么 |
| --- | --- |
| `ss -lntup` | 本机哪些 TCP/UDP 端口正在监听 |
| `ufw status` | 如果安装了 UFW，它管理的规则是什么 |
| 从另一台机器连接 | 这条外部网络路径是否可用 |

没有安装 UFW 不等于整个网络绝对没有任何过滤；系统也可能使用 nftables，云平台还可能有独立规则。

来源：[Debian nftables 说明](https://wiki.debian.org/nftables)、[OpenSSH 端口转发手册](https://man.openbsd.org/ssh)。
