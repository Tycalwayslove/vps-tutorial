# 带宽、流量、延迟与丢包

把网络想成输水管：带宽近似于每秒能通过多少水，流量近似于一段时间累计用了多少水。这个类比帮助区分容量和用量，不能说明所有网络行为。

| 名词 | 直观含义 | 例子与限制 |
| --- | --- | --- |
| 带宽 | 某段链路的传输能力 | 标称 1 Gbps 不代表每次下载都能达到 |
| 吞吐量 | 实际测得的传输速度 | 会受到其他用户、服务器负载和协议开销影响 |
| 流量额度 | 计费周期允许传多少数据 | 3072 GB/月不是每秒 3072 GB |
| 延迟、RTT | 一个请求来回等待多久 | RTT 100 ms 表示一次往返约十分之一秒 |
| 丢包 | 发出的数据包没有按预期到达 | 需要结合终点和实际应用判断 |
| 抖动 | 延迟变化的程度 | 平均延迟相同，忽快忽慢的体验也可能不同 |

## Mbps 与 MB/s

小写 `b` 是 bit（位），大写 `B` 是 byte（字节），8 位组成 1 字节。只做单位换算：100 Mbps ÷ 8 = 12.5 MB/s；扣除开销后，文件下载速度通常达不到这个理论上限。此处使用十进制单位，软件显示的 MiB/s 又有不同换算。

若持续以 10 MB/s 下载 100 秒，数据量约为 1000 MB，也就是十进制的 1 GB。供应商是否分别统计入站和出站，要看套餐的计费说明。

## 水管与水龙头：取较小值只是上限

```mermaid
flowchart LR
  A[电脑] -->|这段可用带宽 200 Mbps| B[中转]
  B -->|这段可用带宽 100 Mbps| C[落地]
  C -->|出口限速 50 Mbps| D[目标网站]
```

理想情况下，这条路径的持续吞吐上限不超过最窄的 50 Mbps，不能写成“一定跑到 50 Mbps”。目标网站限速、拥塞、CPU 开销等都可能继续降低速度。增加中转只有在换来的路径更合适时才可能有收益，多一跳本身不会让网速自动翻倍。

## 怎么比较才有意义

固定客户端、协议、目标文件、测试时长和大致时段；一次只改变线路或一个配置。记录实际吞吐、延迟、失败次数和时间。下载测试会消耗流量，先用小文件确认路径，再决定是否需要测速度。

`ping` 主要测 ICMP 回应，不能证明 HTTPS 或某个代理端口可用。某个中间路由器不回复探测，也不能直接说明后续应用数据都丢失了。故障定位见 [[连接失败的检查顺序]]；影响 TCP 发送节奏的算法见 [[BBR与拥塞控制]]。
