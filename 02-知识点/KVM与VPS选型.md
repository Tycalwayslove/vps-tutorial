# KVM 与 VPS 选型

VPS 是虚拟电脑，虚拟化软件负责把一台物理机器的资源分给多台虚拟机器。KVM 是 Linux 的一种虚拟化技术；虚拟机可以运行自己的操作系统内核。它解释了机器如何被隔开，不代表商家给了你独享物理 CPU 或保证了网络速度。[KVM 官方说明](https://linux-kvm.org/page/Main_Page)

## 看配置时先回答这些问题

| 要确认的事 | 为什么影响教学与使用 |
| --- | --- |
| 能否运行所需系统和内核 | 决定软件、内核参数能否使用；不要仅靠商品名判断 |
| 内存、磁盘是否够用 | 面板、日志、数据库和更新都需要空间 |
| 是否提供公网地址，端口是否受限 | 影响外部设备能否连到服务 |
| 实际网络路径和高峰期表现 | 地理位置近不等于路由短，线路名称也不是性能保证 |
| 流量如何计费、超额会怎样 | 停机、限速与额外收费对维护方式有影响 |
| 是否有控制台与恢复途径 | SSH 不通时，仍需能查看机器并修复 |

“每年多少钱”“某线路固定多少毫秒”只能对应某个时点的具体产品和测量。本文不将视频中的价格、促销或厂商排名当作当前选购结论。我们已经有 meu 和 tyccc，学习主线使用现有资源即可。

## Ubuntu 和 Debian 怎么选

它们都是 Linux 发行版，也就是把内核、系统工具和软件包组织起来的系统。选择受目标软件支持、你能取得帮助并维护的版本即可。本次 tyccc 已验证的环境是 Debian 12；不需要为了对齐视频画面重装成 Ubuntu。面板支持环境应核对 [3x-ui 安装文档](https://docs.sanaei.dev/docs/guide/installation/)。

KVM 是本类实验常见的选择，不能概括成“任何自建代理都必须用 KVM”。容器等环境是否够用，取决于提供的权限和具体功能。继续读 [[VPS与云服务商]]、[[Linux与root]]、[[带宽流量延迟与丢包]]。
