## 保留的教学方法

先画一条请求路径，再给图中的角色起名字；每次只讲少量新词。用转交请求解释代理、用水管解释带宽瓶颈，再说明类比的边界。讲配置时依次回答“在哪里改、改什么、为什么、怎么证明成功”。录制安排见 [[视频分集与画面安排]]，讲稿见 [[入门与链式代理讲稿]]。

## 修正与保留的边界

| 笔记中的表述或倾向 | 教程采用的写法与依据 |
| --- | --- |
| 将 `mzz2017/v2ray-util` 项目的安装路径标成 3x-ui 安装脚本 | 这是不同项目路径，不能作为本教程的 3x-ui 命令。保留 [[02-安装面板与SSH隧道]] 中固定版本的 MHSanaei/3x-ui 来源；核对 [官方仓库](https://github.com/MHSanaei/3x-ui) |
| VPS 必须是海外机器、都有独立公网 IP，KVM 是不可替代的要求 | 区分 VPS 概念与所购产品。本实验需要合适的网络访问条件，KVM 是一种虚拟化方案；见 [[KVM与VPS选型]] |
| Ubuntu 一定最兼容、Debian 只适合老手 | 采用已验证的 Debian 12，不为对齐视频重装；选型按支持范围与维护能力 |
| 某地或某线路固定低延迟，晚高峰一定不卡 | 地理与路由、运营商、时段共同影响结果；不照搬厂商排名或旧价格 |
| BBR 能成倍加速，需要统一重启整机 | 分清算法、内核与具体变更；无本地对照测量就不报倍数，见 [[BBR与拥塞控制]] |
| 协议全部负责加密，三个选项可以随意“配菜” | 分清协议、传输和安全层；本次 VLESS 的 none 依赖外层保护，见 [[协议传输与安全层]] |
| XHTTP 最快，TCP 配置可直接套过去 | XHTTP 是独立传输选项，需核对版本与组合；本次未部署，见 [[XHTTP与传输选择]] |
| 热门或冷门 SNI 能保证效果，Short ID 增加“伪装指纹唯一性” | 按官方字段解释握手、身份与目标条件；保留本次 Apple 成功、Microsoft 失败的观察，不能推出普适原因，见 [[REALITY与Vision]] |
| 必须有域名才能用 TLS | 本次已使用 IP 证书实测。证书身份应匹配访问地址，见 [[03-签发IP证书与自动续期]] |
| Cloudflare 云朵必须永远关闭，或打开就能修复任意节点 | 区分 DNS、HTTP 代理、端口和传输支持，见 [[CDN与DNS代理状态]] |
| 住宅 IP 等于绝对纯净或不封号 | 把资源类型与网站政策分开，见 [[住宅IP与机房IP]]；不作厂商真伪背书 |
| 最窄带宽就是实际网速 | 它是理想上限之一，实际吞吐还受其他条件约束，见 [[带宽流量延迟与丢包]] |
| 链式代理一定加速，跨国住宅连接必然有固定高丢包率 | 是否改善要做相同条件对照；没有本地证据不沿用百分比 |
| 两台海外机器之间天然安全，裸 SOCKS 足够 | 按每段连接判断保护方式；标准 SOCKS 无传输加密，见 [[链式代理与中转落地]] |
| 新建出站、重启面板就等于链式配置成功 | 核对路由 tag、规则顺序、应用到核心以及实际出口，见 [[09-链式代理实验设计]] |
| SSH 或节点不通即可判定 IP 被封，改端口就是完整安全措施 | 分层检查服务、监听、认证、路由与网络；改端口不能代替认证与更新，见 [[连接失败的检查顺序]] |
| 通过在线订阅转换即可解决客户端不支持 | 格式转换不能给核心增加协议实现；转换还会把节点凭据交给服务方。本教程优先使用已核实支持的客户端，见 [[客户端软件与内核]] |
