# 备份、恢复与升级

备份不能只保存几张截图。需要恢复用户、入站和面板设置时，要有数据库；TLS 节点还需要证书、私钥和 ACME 续期状态。

## 本次已经做了什么

通过 SQLite 的在线 backup 接口取得一致数据库副本；把数据库、证书、acme.sh 目录、systemd 服务定义和核心配置文件打包到私人目录。服务器和本机都保存了副本，下载的文件权限为 600。

本地打开副本执行 `PRAGMA integrity_check`，结果 **ok**；计数为 **6 个入站、1 个客户端、6 个关联**。这验证了备份数据库可读且结构完整。没有在正在服务的服务器上执行破坏性的恢复演练，也不能据此宣称跨机器恢复已全面实测。

## 手动备份方法

以下命令在服务器执行，Python 代码块要一次完整粘贴：

```bash
umask 077
python3 - <<'PY'
import sqlite3
source = sqlite3.connect('/etc/x-ui/x-ui.db')
destination = sqlite3.connect('/root/tutorial-backup.db')
source.backup(destination)
print(destination.execute('PRAGMA integrity_check').fetchone()[0])
destination.close()
source.close()
PY
tar -czf /root/tyccc-tutorial-backup.tar.gz /root/tutorial-backup.db /root/cert/tyccc-ip /root/.acme.sh /etc/systemd/system/x-ui.service /usr/local/x-ui/bin/config.json
```

输出 `ok` 后，从**电脑终端**下载到仓库外：

```bash
scp root@VPS_IP:/root/tyccc-tutorial-backup.tar.gz /你的私人备份目录/
```

备份里含有效密码、私钥和 ACME 账号。不要上传到本教程仓库。`tar` 提示移除开头的 `/` 是避免解包时直接写绝对路径的正常行为。

## 真要恢复时

先在另一台实验机或停机窗口操作，保留故障现场副本。确认系统架构、3x-ui 版本与原配置兼容。将压缩包解到**临时目录**检查，不要直接向 `/` 覆盖解包。

```bash
mkdir -p /root/restore-check
tar -tzf /root/tyccc-tutorial-backup.tar.gz
tar -xzf /root/tyccc-tutorial-backup.tar.gz -C /root/restore-check
```

停掉 x-ui 后，用检查过的数据库替换 `/etc/x-ui/x-ui.db`，恢复 `/root/cert/tyccc-ip` 和 `/root/.acme.sh` 的正确目录及权限，再确认服务定义和 cron。恢复前应另存现有 DB；不要遗漏可能存在的 SQLite WAL/SHM 状态，停止服务并确保没有进程持有数据库后再替换。

如果新机器 IP 不同，必须改监听地址、客户端地址并为新 IP 重新签发证书；旧 IP 证书不能自动代表新 IP。启动后按 [[06-连接验证与结果]] 重测，而不是只检查面板能登录。

## 升级前的顺序

记录当前版本 → 阅读官方发布说明 → 做私人备份 → 在测试环境核对兼容 → 更新 → 检查服务与节点。升级可能变更数据库结构；降级二进制不一定能读升级后的数据库，所以回退需要对应版本和升级前备份。

当前 Xray 对部分旧协议有弃用提示，未来是否继续支持应查当时文档。本次没有开启自动更新面板/核心来追逐版本。
