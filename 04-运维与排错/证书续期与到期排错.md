# 证书续期与到期排错

本次 IP 证书只有约 160 小时有效期，维护重点是自动续期，不能等几个月后才检查。签发过程见 [[03-签发IP证书与自动续期]]。

## 日常查看

在服务器运行：

```bash
openssl x509 -in /root/cert/tyccc-ip/fullchain.pem -noout -dates
crontab -l
systemctl is-active x-ui
```

关注 notAfter、ACME 定时任务是否存在、服务是否 active。首次证书到期时间为 2026-09-14 00:02:33 UTC（北京时间 08:02:33）。后续成功续期后，这个时间应该向后变化。

本次已配置四次/日的检查任务、稳定证书路径和 reloadcmd；**尚未观察未来自动续期发生**。证书机构的建议窗口可能影响实际续期时间，不能只按 `--days 3` 推断精确时刻。

## 失败时按顺序查

| 现象 | 检查 |
| --- | --- |
| 连接时报过期 | 看部署文件 notAfter；再检查客户端实际收到的证书 |
| ACME 验证超时 | 服务商防火墙、系统防火墙、TCP 80 是否能到达 |
| 80 被占用 | 用 `ss -lntp` 找进程；不要直接杀掉陌生业务 |
| 签发成功但客户端仍旧证书 | `--install-cert` 的路径和 reloadcmd 是否正确；面板引用是否同一文件 |
| 全部 TLS 入口一起出错 | 检查共享证书、时间同步、文件权限 |
| REALITY 正常但 TLS 入口失败 | 两种身份机制不同，这不矛盾 |

需要查看 ACME 的当前判断时可手动运行普通检查：

```bash
/root/.acme.sh/acme.sh --cron --home /root/.acme.sh
```

不需要续期时返回跳过是正常结果。不要反复加 `--force` 重新签发来试错；先修复原因，并参考证书机构速率限制。诊断日志可能含账户信息，留在私人目录。

成功续期时 reloadcmd 会重启 x-ui，现有连接可能短暂中断。以后如果改成其他服务管理方式，需要同步维护重载命令。

来源：[acme.sh](https://github.com/acmesh-official/acme.sh)、[Let's Encrypt 挑战类型](https://letsencrypt.org/docs/challenge-types/)、[速率限制](https://letsencrypt.org/docs/rate-limits/)。
