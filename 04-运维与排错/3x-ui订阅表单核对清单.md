# 3x-ui 订阅表单核对清单

这是一份针对 MEU 当前服务的实操记录。它把“订阅能打开”和“v2rayN 能导入”分开检查。订阅链接本身含有访问凭据，不能截图、转发或提交到公开仓库。先读 [[UUID密码与订阅链接]]、[[TLS证书与HTTPS]]、[[MEU域名节点与IP证书兼容性]]。

## 这次问题的根因

最初订阅接口可以用 HTTPS 打开，证书也正确，但内容是**一整段 Base64 编码**。这不是加密，只是把文本换成另一种写法；部分客户端会自动还原，部分版本或导入路径会识别失败。

3x-ui 中对应的字段是 `subEncrypt`，面板通常显示为“订阅内容加密”或相近名称。MEU 已将它关闭。现在订阅响应是五行标准链接，每行一个节点，v2rayN 可按常规订阅链接列表处理。

## 面板设置 → 订阅：当前正确表单

打开 3x-ui 的“面板设置 → 订阅”。下面的“已核对”指服务器当前生效值，不要把示例中的路径、客户端 ID 或链接复制给别人。

| 表单项 | MEU 已核对值 | 为什么这样填 |
| --- | --- | --- |
| 启用订阅服务 | 开启 | 允许客户端用订阅链接获取节点。 |
| 监听地址 | 留空 | 让服务监听公网接口；若只想经 SSH 隧道使用，应改为 `127.0.0.1`。 |
| 订阅端口 | `2096` | 这是订阅 HTTPS 服务的端口，不是代理节点端口。 |
| 订阅路径 | 已设置的随机私密路径 | 增加猜测难度；它仍是凭据，泄露后应更换。 |
| 订阅域名 | 留空 | 当前使用 IP TLS 证书，因此由公网 IP 提供服务。若改回域名，证书 SAN、连接地址和 SNI 必须同时匹配。 |
| 订阅证书 / 私钥 | 指向存在的 IP 证书文件 | 服务器会以这张证书证明订阅站点身份。私钥必须只由 root 读取。 |
| 订阅内容加密 `subEncrypt` | **关闭** | 输出直接可导入的一行一条 URI，避免 Base64 兼容性问题。 |
| JSON 订阅 | 关闭 | 当前客户端使用普通 URI 列表；不额外引入格式分支。 |
| Clash 订阅 | 关闭 | 没有使用 Clash 客户端时无需开放。 |

保存后按面板提示重启 x-ui。不要只看“保存成功”；重启后必须按下文的验收步骤检查。

## 每条入站必须与订阅一致

3x-ui 生成订阅时会读取入站的“分享地址”。因此不能只修改 TLS 区域的 SNI；地址、分享地址、证书身份要组成同一套身份。

| 入站 | 传输与端口 | 订阅中应出现的身份字段 |
| --- | --- | --- |
| VLESS + REALITY | TCP `443`，RAW/TCP | 分享地址为 MEU 公网 IP；REALITY 参数已配置。 |
| Shadowsocks | TCP/UDP `8388` | 分享地址为 MEU 公网 IP；没有 TLS SNI。 |
| VMess + WebSocket | TCP `8080`，WebSocket | 分享地址为 MEU 公网 IP；没有 TLS SNI。 |
| VLESS + WebSocket + TLS | TCP `8443`，WebSocket + TLS | 分享地址、TLS SNI、WebSocket Host 都是 MEU 公网 IP；证书文件存在。 |
| Hysteria2 | UDP `443`，Hysteria + TLS | 分享地址和 TLS SNI 都是 MEU 公网 IP；证书文件存在。 |

当前的一个已启用订阅客户端关联了这五个入站，所以响应应是五条链接。少一条通常是客户端没有关联该入站、入站被禁用，或客户端本身被禁用。

## 保存后的验收顺序

1. 在自己的电脑上用浏览器或命令行访问订阅 URL。不要把 URL 贴到在线转换网站。
2. 确认返回 `HTTP 200`，浏览器没有证书警告。
3. 将正文保存到本地文本文件查看。正确结果是一行一条链接，开头依次可见 `vless://`、`ss://`、`vmess://`、`vless://`、`hysteria2://`。
4. 在 v2rayN 的订阅分组中执行“更新订阅”，再检查新增节点数量是否为五条。
5. 特别检查 VLESS WebSocket + TLS 与 Hysteria2：地址和 SNI 都应为 MEU 公网 IP，并保持“跳过证书验证”关闭。

本次改动后的外部验收结果是：HTTPS 证书验证通过、状态 `200`、响应 MIME 类型为 `text/plain`、五条 URI 均存在。服务 `x-ui` 处于 active 状态；五条入站和一个关联全部入站的订阅客户端都处于启用状态。

## 仍然导入失败时先看什么

| 现象 | 优先检查 | 处理方向 |
| --- | --- | --- |
| 浏览器提示证书错误 | 订阅域名/IP 与证书 SAN | 换成与地址匹配的证书；不要开启跳过验证掩盖问题。 |
| 返回的是一大段没有 `://` 的字符 | `subEncrypt` | 关闭后保存并重启，再重新获取订阅。 |
| 少了一个协议 | 客户端与入站的关联、入站启用状态 | 在“客户端”页面勾选该入站并保存。 |
| 导入后还是旧域名 | 入站的分享地址、TLS SNI、WS Host | 三处统一为 IP，再更新订阅。 |
| 节点存在但“运行 Core 失败” | v2rayN 的日志与“跳过证书验证” | 这是本机核心配置问题，按 [[MEU域名节点与IP证书兼容性]] 检查。 |

这里的“订阅内容加密”不能替代 HTTPS：Base64 谁都能还原，真正保护传输和服务端身份的是 TLS。来源：[3x-ui 官方文档](https://docs.sanaei.dev/zh/docs/)、[Xray TLS 配置](https://xtls.github.io/config/transports/tls.html)。
